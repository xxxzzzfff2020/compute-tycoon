# Historical Audit Documents

Many files under `docs/audit/`, `docs/reports/`, `docs/product/`, and `docs/release/` are point-in-time evidence from private development gates. Status values such as `NOT_RELEASE_CANDIDATE`, `BLOCKED`, or `NOT_AUTHORIZED` describe the date and baseline recorded in that document; they do not override the current public repository status.

Current release truth is published in this order:

1. GitHub Releases and the tag target
2. `CHANGELOG.md`
3. `docs/oss/RELEASE_NOTES_v1.0.0-rc.1.md`
4. Historical audit documents, for their original date only

Historical evidence remains public because failures, blocked gates, and later corrections are part of this repository's reproducible AI-agent development case study.
