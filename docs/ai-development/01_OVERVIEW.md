# AI 驱动开发总览（AI-Agent-Driven Development Overview）

> 本文面向公开读者，说明《算力大亨 Compute Tycoon》H5 是如何在"人类治理 + AI 编码 + 自动化证据 + 真人验收"模式下开发的。

## 1. 开发模式总览

本项目采用 **AI-agent-driven** 开发方式，四要素缺一不可：

| 要素 | 内容 | 文档 |
|---|---|---|
| 人类 Product Owner 治理 | 产品方向、范围、验收裁决权始终由人掌握 | `docs/ai-development/02_PRODUCT_GOVERNANCE.md` |
| AI 编码 | 总执行 Agent 编排，文本/代码 Worker 产出，Codex 审计与修复 | `docs/ai-development/03_AGENT_ROLES.md` |
| 自动化证据 | 单元测试、端到端测试、经济模拟、浏览器验证等构成完成标准 | `docs/ai-development/05_EVIDENCE_DRIVEN_QA.md` |
| 真人验收门 | 创始/负责人集中评审、真机舒适度与平台门禁，未通过不构成发布 | `docs/ai-development/02_PRODUCT_GOVERNANCE.md` |

工作方式：**单任务、单负责人、单一验收标准、facts-first、证据驱动完成**（详见 `docs/ai-development/04_DEVELOPMENT_WORKFLOW.md`）。

## 2. 游戏简介

《算力大亨 Compute Tycoon》是一款放置经营（incremental/tycoon）游戏，玩家经营一家 AI 算力创业公司，让收入、算力与规模持续膨胀。完整主线：

```text
AI 工作室 → 模型研发 → 接单 → 服务器 → 集群 → 算力中心
→ 三次迭代 → 地月网络 → 戴森终局
```

具体流程（与 `docs/PRODUCT_CONTRACT.md` 一致）：

1. **AI 创业工作室**：获得第一款 AI 模型，接第一批订单，用租赁算力处理，获得收入，训练/研发更强模型，解锁自动经营；里程碑取得第一台自有服务器。
2. **模型研发**：首发 6 个模型，各有独立职责（基础收益、处理速度、高价值业务、自动经营、研发速度、旗舰效率）；进度满免费研发，重复研发转为图鉴等级。
3. **接单经营**：手动选单仅前期；自动经营按业务组合占比运转，订单按吞吐切三档结算。
4. **服务器集群**：1 台自有算力起步，3/5/8 台自动永久解锁三项架构节点（全局倍率约 ×1.45/×2.10/×3.05），8 台构成完整集群。
5. **算力中心**：8 台折为集群核心机房，四项全局基础设施（电力/算力卡/光模块/存储）、瓶颈识别、机房 2/3 投产与旗舰工程，最终解锁算力档案馆。
6. **三次迭代**：R1/R2/R3 完成时代工程并手动领取奇点核心后执行地球技术迭代，永久倍率依次 ×1.5、×2.0、×2.0；R3 揭示地外算力计划。
7. **地月网络（Stage 4）**：手动启动，完成地月一体化算力网。
8. **戴森终局（Stage 5）**：完成戴森算力球，生成传奇档案，进入永续经营；不存在第四次迭代。

玩家面保持低负担：禁止复杂模型配队、逐服务器硬件、运输/燃料、随机事件、签到、新货币与戴森后无限解锁。

## 3. H5 重构背景

- 项目早期为 TapTap Maker（Lua）版本；当系统设计超载（模型、订单、服务器、基础设施、迭代等模块叠加后难以继续承载）时，决定以 H5（TypeScript + Vite）重建。
- **H5 重建原则**：只提取产品合同与体验参考，不复制 Lua 代码；Lua 版本冻结为只读工程参考。
- 产品事实源：`docs/PRODUCT_CONTRACT.md`（历史工程合同）与 `docs/product/H5_FINAL_PRODUCT_CONTRACT.md`（Release Candidate 权威合同）。
- 重建过程保留合同化治理：范围、节奏、广告、存档、平台开关都有明确合同与验收门，避免"越写越复杂"重演。

## 4. 完成标准（概览）

- 类型检查、单元测试（当前基线 31 个文件 / 370 项）、端到端测试、生产构建全部通过。
- 经济模拟 8 策略 × 1000 局校验节奏目标（首服 8–12 分钟、八服 28–36 分钟、机房 2 40–50 分钟等）。
- 浏览器矩阵与 soak 验证响应式、DOM 稳定、无控制台错误。
- 真人验收门：创始人集中评审（A–J 检查点）与真机/平台门禁（见 `docs/ai-development/05_EVIDENCE_DRIVEN_QA.md`）。
