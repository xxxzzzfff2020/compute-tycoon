# 开发工作流（Development Workflow）

> 本项目的工作纪律：单任务、单负责人、单一验收标准；facts-first；证据驱动完成；Git 与文件为事实源。

## 1. 单任务 / 单负责人 / 单一验收标准

- **单任务**：每个工作单元只解决一个问题；任务说明必须写明输入（事实与来源）与输出（交付物）。
- **单负责人**：一个任务只有一个 owner（总执行 Agent、Worker 或 Codex 之一），owner 对交付负责。
- **单一验收标准**：任务启动前写下一个可判定的验收标准（如"该里程碑达成 + 对应测试通过 + 浏览器验证无控制台错误"），验收标准不随实现漂移。
- 任务关闭时必须回答：交付了什么、依据什么证据、是否满足验收标准。

## 2. Facts-first（事实优先）

- 一切决策先核对事实源：
  - 产品事实：`docs/product/H5_FINAL_PRODUCT_CONTRACT.md`（权威）与 `docs/PRODUCT_CONTRACT.md`（历史）；
  - 存档事实：`docs/SAVE_CONTRACT.md`；
  - 经济事实：`docs/ECONOMY_SIMULATION.md` 与 `scripts/simulate-economy.ts`；
  - 代码事实：`src/`、`tests/`、`scripts/`。
- 不凭印象下结论；任何数值、行为、边界主张都要能指到代码或文档行。
- 旧文档与新结论冲突时，以"最新、最权威、且有记录"的一方为准，并把冲突记录到文件（本项目做法：旧文档加"已被取代"标注）。

## 3. 证据驱动完成（Evidence-Driven Completion）

任务"完成"必须同时满足：

1. **测试**：相关单元/契约测试通过（新增行为先补测试，若有既有测试模式）；
2. **经济模拟**：涉及节奏/数值的任务运行 `scripts/simulate-economy.ts`（8 策略 × 1000 局）核对目标门；
3. **浏览器验证**：涉及界面/运行时行为的任务，通过浏览器自动化（`scripts/` 下验证脚本）核对关键流程、DOM 稳定、无控制台错误；
4. **构建**：生产构建（`npm run build`）通过。

证据记录在 `evidence/`、`docs/reports/` 与任务报告；没有证据的"应该没问题"不算完成。

## 4. Git 与文件为事实源

- **Git 是提交事实**：变更记录、分支、标签、验收基线都以 Git 为准；重要的验收结论打 tag（如评审候选、创始人评审就绪等基线）。
- **文件是讨论事实**：产品合同、存档契约、经济模拟、报告都落盘成文档；口头/临时结论必须写下来才生效。
- **先落盘再实施**：涉及产品方向的任务先更新合同/裁决文档，再实施代码。
- **审计可追溯**：每个重要任务产出报告文档（intake audit、验收、硬化、收敛报告），说明起止基线、验证矩阵与结论边界。
- **公开镜像**：公开仓库从一次性基线快照起步，Git 历史不携带生产仓库私密内容（见 `docs/oss/OSS_SCOPE_AND_SANITIZATION.md`）。

## 5. 任务生命周期

```text
产品裁决/规格（Human 或合同）
  → 任务卡（单一验收标准，owner 明确）
  → 实现（Worker / Codex）
  → 证据（测试 + 模拟 + 浏览器 + 构建）
  → 审计（Codex intake/review）
  → 真人验收门（涉及产品/发布时）
  → 关闭（记录交付与证据）
```

## 6. 反模式（禁止）

- 一个任务多个 owner、多个验收标准、验收标准临时放宽；
- 以"直觉/经验"代替代码与文档事实；
- 无证据宣称完成；
- 口头裁决不落盘；
- AI 单方面扩大产品范围。
