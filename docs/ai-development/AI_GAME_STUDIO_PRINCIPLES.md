# AI 游戏工作室通用治理原则（AI Game Studio Principles）

> 本文是工作室层面可复用的治理原则，不绑定单一游戏，也不泄漏任何私人信息。适用于所有以"人类治理 + AI 编码 + 自动化证据 + 真人验收"模式开发的游戏项目。

## 1. Facts First（事实优先）

- 决策以可验证的事实为准：产品合同、存档契约、代码、测试、模拟结果、Git 记录。
- 任何主张（数值、行为、边界、结论）都要能指到具体来源；"凭印象/直觉"不构成依据。
- 事实冲突时，以"最新、最权威、且有记录"的一方为准，并把冲突与裁决写进文件。

## 2. Product Authority（产品权威唯一）

- 产品方向、范围与验收结论由 Human Product Owner 裁决。
- 产品合同是产品事实源；AI 不得擅自改变产品方向、数值、奖励语义或范围。
- 已冻结的方向（如系统清单、迭代次数、终局边界、商业化开关）不可由 AI 单方面解冻。

## 3. Engineering Authority（工程权威明确）

- 工程实现由工程角色（总执行 Agent / Worker / 审计 Agent）按合同执行；工程质量以自动化证据衡量。
- 工程角色的职责边界在角色文档中写明（本仓库见 `docs/ai-development/03_AGENT_ROLES.md`）。
- 工程结论与产品裁决冲突时，工程负责实现与证明，产品负责裁决。

## 4. One Task, One Owner, One Acceptance（单任务 / 单负责人 / 单一验收标准）

- 每个任务只有一个 owner、一个验收标准。
- 任务启动前写明输入（事实与来源）与输出（交付物）；验收标准不随实现漂移。
- 多任务并行必须保证每个任务独立可验收；禁止一个任务多个负责人。

## 5. Evidence-Driven Completion（证据驱动完成）

- "完成"= 验收标准 + 可复现证据（测试、模拟、构建、运行时验证），不止是代码写出来了。
- 证据要落盘（报告、JSON、清单），并且能重跑复核。
- 自动化证据通过 ≠ 真人/真机/发布通过；证据边界必须明确标注。

## 6. AI Capability Boundaries（AI 能力边界）

- 文本/代码 Worker 纯文本工作，禁止视觉输入；视觉验证由浏览器自动化承担。
- 每个 AI 角色只做自己职责内的事：编码的不裁决产品，审计的不代签验收。
- 遇到能力边界（如真机验证、平台账号、法务判断）必须上交人，不假装完成。

## 7. Git and Files as Source of Truth（Git 与文件为事实源）

- Git 记录提交与验收基线；文档记录合同、契约、报告与裁决。
- 先落盘再实施：产品裁决先写进文档，再进入开发。
- 公开/分享时只携带公开范围，不携带内部历史与私密信息（脱敏规则见 `docs/oss/OSS_SCOPE_AND_SANITIZATION.md`）。

## 8. Player Experience over Code Volume（玩家体验优先于代码量）

- 价值以玩家体验衡量：核心循环是否有趣、节奏是否成立、反馈是否清晰、负担是否低。
- 代码量/系统数量不是目标；"越写越复杂"是风险信号，出现时应回到产品合同做减法。
- 体验优化若改变规则（数值、节奏、奖励语义），仍属于产品裁决范围。

## 9. 落地检查清单

- [ ] 产品合同可追溯到 Human Product Owner 裁决；
- [ ] 每个任务有 owner、验收标准、证据；
- [ ] 结论有文件/代码可指；
- [ ] 无 AI 单方面扩大产品范围；
- [ ] 纯文本 Worker 无视觉输入；
- [ ] 自动化结论与真人验收门分开标注；
- [ ] 公开内容零私密信息。
